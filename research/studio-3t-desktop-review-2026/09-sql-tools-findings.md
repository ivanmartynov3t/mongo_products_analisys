## Scope note (important)

Per this audit's brief, F-SQL here is scoped to **querying MongoDB using SQL syntax** (SQL-to-MongoDB query translation/execution) — not SQL⇄MongoDB migration, which belongs to F-TRANSFER (covered by a separate agent). However, the *existing* `feature-dictionary.md` (F-SQL section, lines 304–320) and `features/sql-tools/feature-matrix.md` currently bundle both the SQL query engine (`SQL-expressions`, `SQL-join-mapping`, `SQL-code-gen`, `SQL-query-manager`) **and** the bidirectional migration wizards (`SQL-migration*`, `SQL-export-*`) plus in-place `SQL-reschema` under one Feature ID. This is a structural mismatch worth flagging to whoever owns the dictionary: the migration/reschema sub-features are implemented in an entirely separate part of the source tree (`t3.sqlnosql`, `t3.dataman.gui.sqlimport`, `t3.dataman.gui.sqlexport`, `t3.dataman.gui.reschema` — JDBC connectors, mapping wizards, schema-restructuring jobs) from the SQL *query* engine (`t3.utils.mongodb.sql` + `t3.dataman.gui.sqltab` — an ANTLR-based SQL parser that translates to aggregation pipelines). This report only re-verifies the query-engine sub-features in depth; the migration/export/reschema rows are left as-is (not re-verified here) since they are F-TRANSFER's remit.

## Undocumented capabilities found (new sub-feature ID candidates)

All of the below are additions to the existing `SQL-expressions` sub-feature (extending its description), not new top-level sub-feature IDs — they are refinements of one already-confirmed capability rather than distinct product surfaces:

- **GLOB and REGEXP predicate operators** in SQL WHERE clauses, in addition to LIKE, with optional `ESCAPE` clause support for LIKE/REGEXP/GLOB. Source: `product-suite/data-man-mongodb-ent/src/main/java/t3/utils/mongodb/sql/SQLiteExpressionVisitor.java`, `visitExpr_RegEx` (~line 104–160); `t3/utils/mongodb/sql/LikeToRegexConverter.java`, `GlobToRegexConverter.java`.
- **STDEV / STDEVP aggregate functions** (sample and population standard deviation), translating to `$stdDevSamp` / `$stdDevPop` respectively — usable alongside the documented COUNT/SUM/AVG/MIN/MAX in GROUP BY/HAVING. Source: `t3/utils/mongodb/sql/AggregateExpression.java` lines 194–237, `ExpressionFunctionCalls.java` lines 163–171.
- **RAND / RANDINT / RANDDOUBLE functions** for generating random long/int/double values directly in a SQL query. Source: `ExpressionFunctionCalls.java` lines 43–58.
- **Additional BSON type constructors** beyond what the matrix lists: `MaxKey()`, `MinKey()`, `Symbol(...)`, `Undefined()`/`BsonUndefined()`, `NumberLong(...)`. Source: `ExpressionFunctionCalls.java` lines 108–130.

No genuinely new top-level SQL-Tools capability (e.g., a BI/ODBC-JDBC-driver server exposing MongoDB as a SQL data source for external tools like Tableau/Power BI) was found. A repo-wide search for "ODBC" and BI-tool terms (Tableau, Power BI) turned up nothing under `product-suite/`; the only JDBC-related driver-management UI found (`t3/utils/gui/dialogs/propertiesdialog/tabs/JDBCDriversTab.java`) manages *user-supplied JDBC drivers for connecting to external relational databases* (i.e., for the SQL migration direction), not a driver that exposes MongoDB collections to external SQL clients.

## Recent changes (last ~24 months, git + release notes)

Git log (`git log --since="24 months ago" -- .../t3/sqlnosql .../t3/dataman/gui/sqltab .../t3/utils/mongodb/sql .../t3/utils/sqlexport .../t3/utils/sqlimport .../t3/dataman/gui/reschema third-party/antlr`) returned 27 commits, the large majority pure refactors (moving methods between utility classes, import reorganization, code-style splits) or narrow bug fixes. Only two are user-facing for the query-engine scope:

- `23452192413` (Jul 2026) — "KONG-11118: Fix NPE when opening SQL/Map-Reduce tab from a collection" — touches both `MapReduceTab.java` and `SqlTab.java`.
- `61d89bc66b2` (May 2025) — "KONG-10223: Remove SQL restrictions that no longer apply" — a cosmetic change removing a stale Pro-edition label suffix from `SqlFormat.java`; **not** an actual licensing/feature-gate change (the SQL query tool's "Pro/Base+ only" gating documented in the current matrix is not contradicted by this commit).

No commits at all touched `SQLiteParser.g4`/`SQLiteLexer.g4` in the window — the SQL query grammar itself has been stable for at least 24 months.

Release notes (`release/studio-3t/changelog.txt`, entries from `2024.4.0` (30-Sep-2024) through `2026.12.0` (17-Jul-2026), i.e. within the 24-month window): SQL-tools-relevant entries found are all on the **migration** side (Migration from SQL: virtual-column decimal handling, array preview limits, dialog fix) and one connection-storage improvement ("Local File Support - Enable saving and loading MongoDB and SQL connections from the local file system (including Git-backed folders)", `2026.4.0`) that applies to SQL connection definitions generally (used by the migration wizards), not to the SQL *query* tab specifically. **No changelog entries were found for the SQL Query tool itself** (no new expressions, functions, or join behavior announced) in this window — consistent with the git-log finding of a stable, unchanged query engine. `site/` had no matching directory to search for changelog content; `eulas/` contained no SQL-related mentions.

## Confidence / spot-check notes

- High confidence: SQL-expressions core surface, SQL-code-gen language list, SQL-query-manager — verified directly against implementation classes (visitor methods, function-constructor maps, generator class list), not just documentation or comments.
- High confidence: the "no visual JOIN mapping editor" and "single equality comparison per JOIN" findings — verified by reading `JoinExpressionVisitor.java` in full and confirming the absence of any join-mapping widget class under `dataman/gui/sqltab/`.
- Medium confidence: the LUUID-constructor discrepancy. Absence of a `LUUID` key in `ExpressionFunctionCalls`'s static map is strong negative evidence, but it's possible LUUID values are recognized via a different code path (e.g., as a literal syntax rather than a function call) that this pass did not locate — flagged as "unverified/likely inaccurate" rather than "confirmed absent."
- Not independently re-verified (relies on existing matrix + light spot-check only, per this audit's scope boundary): SQL-migration*, SQL-export-*, SQL-reschema rows — deep re-verification of these is F-TRANSFER's remit; only enough was checked here (directory/class existence, Task Scheduler wiring for Reschema) to avoid contradicting the existing matrix without evidence.
- No BI/ODBC/JDBC-driver-server capability exists for exposing MongoDB as a SQL data source to third-party tools — this was an explicit thing to look for per the task brief, and the negative result (nothing found across `product-suite/`) is reported as a confirmed absence, not a gap in search effort.
