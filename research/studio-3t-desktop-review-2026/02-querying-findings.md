## Note on source layout

The task brief's expected path `t3/dataman/mongodb/gui/{querycode,search,history,bookmarkmanager,queryprofiler}` does not exist in the current checkout. The real locations are:

- Visual Query Builder: `t3/dataman/mongodb/gui/querybuilder/` (not `dataman/mongodb/gui/querybuilder` docs assumed a `gui/querycode` sibling — code generation actually lives one level up, at `t3.dataman.gui.querycode`)
- Query code generation widget: `t3/dataman/gui/querycode/QueryCodeWidget.java`
- Code generator implementations/registry: `t3/utils/codegenerators/` (`ProgramCodeGenerators.java`, one subpackage per language)
- Cross-collection value search ("Search in…"): `t3/dataman/gui/search/` (`SearchTab.java`, `FilterQueryWidget.java`) + `t3/utils/ValueSearcher.java`
- Query history / saved queries / Query Manager: `t3/dataman/gui/bookmarkmanager/` + `t3/dataman/gui/history/`
- Query Profiler: `t3/dataman/gui/queryprofiler/` (this is the live-editing/find-slow-queries profiler tab, in scope per brief's carve-out; the deeper performance-analysis views belong to F-IDX)
- GridFS viewer: `t3/dataman/gui/gridfsview/`
- Autocomplete engine shared by query bar / shell: `t3/dataman/autocomplete/` (`QueryAutoCompletion.java`, `MongoContentAssistProcessor.java`)

## Undocumented capabilities found (new sub-feature ID candidates)

- **Cross-collection Value Search ("Search in…")** — `t3/dataman/gui/search/SearchTab.java` (1517 lines) and `t3/utils/ValueSearcher.java`. Searches a chosen set of collections in a database for a literal value and/or field name, with case-sensitive and regex toggles (`ValueSearcher.search(..., boolean caseSensitive, boolean regex, ..., SearchType searchType)`, `utils/ValueSearcher.java:31-39`). Three search modes: `VALUE_NAME` ("Field value and name"), `VALUE` ("Field value"), `NAME` ("Field name") (`ValueSearcher.java:246-260`). Gated by `AppFeatures.VALUE_SEARCH`, present from `PROFESSIONAL` tier up (`utils/Edition.java:59`). Changelog: introduced field-name search in 2022.8.0 ("Enhanced Value Search"), diacritics case-sensitivity fix in 2024.5.0. This is a distinct capability from `QUERY-filter-bar`/VQB (it searches *across* collections for a value rather than filtering one collection) and has no existing `QUERY-*` ID. Recommend a new ID, e.g. `QUERY-value-search`.
- **Query bar autocomplete engine is shared infrastructure** — `t3/dataman/autocomplete/QueryAutoCompletion.java`, `AggregationAutoCompletion.java`, `MongoScriptAutoCompletion.java`, `MongoContentAssistProcessor.java`, `ContentAssistProcessor.java` form one autocompletion framework reused by the Collection Tab query bar, the Aggregation Editor, and IntelliShell — worth noting in the feature report's narrative that `QUERY-filter-bar`'s autocomplete is not bespoke to the query bar; it is the same engine documented under `SHELL-autocomplete`. No new ID needed, but the feature-report's "distinct from Compass's shell" framing should note the shared engine explicit for accuracy.
- **"Restore Default Query" per-collection button and "auto-run default query" toggle** — referenced heavily in changelog (2025.2.0 "Added a preference option to toggle whether the default query runs when opening the tab"; multiple older fixes to "Restore Default Query button"). This is a specific, named capability that supports `QUERY-history`'s "Default query per collection (auto-runs on open)" claim but is granular enough it could be called out as its own row/bullet rather than folded into history.

## Confidence / spot-check notes

- The single most significant correction from this pass is **licensing/edition gating**: the current feature-matrix.md repeatedly states "All editions" for `QUERY-filter-bar`, `QUERY-history`, `QUERY-manager` (non-SQL types), and `QUERY-vqb-core`/`QUERY-vqb-proj-sort`. Source evidence (`utils/Edition.java`, `utils/App.java:241-268`, and usage sites across `bookmarkmanager`, `querybuilder`, `intellishell`, `sqltab`) shows `SAVED_QUERIES_AND_HISTORY` and `VISUAL_QUERY_BUILDER` are both absent from the `FREE` edition (present in `ROBO`/Community only for `SAVED_QUERIES_AND_HISTORY`; absent from both `FREE` and `ROBO` for `VISUAL_QUERY_BUILDER`). This should be treated as a high-confidence finding since it is based on direct enum-membership evidence in `Edition.java`, not inference — but a human should confirm the current mapping from `Edition` enum values (`ROBO`, `FREE`, `CORE`, `PRO`, `PROFESSIONAL`, `ENTERPRISE`) to the public-facing tier names Studio3T actually markets today (`CORE`/`PRO` share `PROFESSIONAL`'s feature set per line 122/124, so the practical distinction is Free/Community vs. everything else for these specific sub-features).
- `QUERY-view-split` and `QUERY-charts-dashboards` were added to the dictionary on 2026-07-28 apparently from studio3t.com marketing pages per the dictionary's own changelog note, not from a source-code check — this audit found **no corroborating source code** for either. Recommend flagging both as absent/unverified pending a check of whether they exist under a different, unexamined directory (this audit searched the full `data-man-mongodb-ent/src/main/java` tree for `SplitPanel`, `dashboard`, `sync scroll`, `side-by-side` and found nothing).
- Result-view sub-features (`QUERY-view-tree`, `QUERY-view-table`, `QUERY-view-json`, `QUERY-doc-dialog`, `QUERY-multi-update`, `QUERY-copy-options`, `QUERY-inline-edit`, `QUERY-batch-edit`, `QUERY-undo-redo`, `QUERY-pagination`, `QUERY-run-variants`, `QUERY-cancel`, `QUERY-perf-timer`, `QUERY-collation`, `QUERY-max-time`, `QUERY-projection`, `QUERY-sort`, `QUERY-skip-limit`, `QUERY-ai-builder`) were **not** independently re-verified in this pass — the investigation scope given (`querycode`, `search`, `history`, `bookmarkmanager`, `queryprofiler`, plus the VQB directory actually found) does not include the result-view/CollectionViewer code (`t3/utils/collectionview/CollectionViewer.java`, a 3000+ line file referenced heavily above) where those would live. These rows are left as previously documented status; a follow-up pass should target `t3/utils/collectionview/` specifically.
- All licensing claims are traced to `t3/utils/Edition.java` and `t3/utils/AppFeatures.java` as of the current working tree — these are internal enum names/comments, not public marketing copy, so cross-check against studio3t.com pricing pages is still advisable before publishing externally-facing edition claims (matches the existing product-report.md caveat that "Exact edition names are unverified — the pricing page returned 404 at analysis time").
