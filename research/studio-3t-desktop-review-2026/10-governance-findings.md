## Scope note

The current `feature-matrix.md`/`feature-report.md` for this folder explicitly say the Desktop IDE-native governance capability matrix "has not yet been authored" — only a pointer table to the split-out platform products (3T Lens, 3T Access, 3TL Bridge, 3T Explore). This findings file investigates the eight Desktop-IDE-native sub-feature IDs the pointer table names by reference (`GOV-readonly-mode`, `GOV-rbac-users`, `GOV-rbac-roles`, `GOV-audit-log`, `GOV-collection-compare`, `GOV-collection-sync`, `GOV-data-masking`, `GOV-cred-protection`), plus the broader set of `GOV-*` IDs in `feature-dictionary.md` that plausibly map to Desktop IDE code (`GOV-network-policy`, `GOV-telemetry`/`GOV-telemetry-config`, `GOV-startup-policy`, `GOV-cli-policy`, `GOV-ai-controls`, `GOV-cred-storage-os`, `GOV-isolated-edition`, `GOV-air-gapped`, `GOV-rbac-inheritance`, `GOV-rbac-tree`, `GOV-rbac-actions`, `GOV-protect-mode`). Platform-tier IDs (`GOV-platform-*`, `GOV-002`…`GOV-013`) are out of scope here — they belong to the separately split products and were not re-verified against this Desktop IDE source tree.

All evidence below is from `product-suite/data-man-mongodb-ent/src/main/java/t3/` in the `3t.tools` repo (read-only), current branch `KONG-11077-No-scroll-bar-on-linux-2` at commit `435d6844a3a`.

| `GOV-audit-log` | Referenced only (implied "confirmed" via comparison reports); described as "Track queries, modifications, and connections with timestamp and user info" | **partial — narrower than documented** | Two independent, non-overlapping mechanisms exist, neither of which logs queries: (1) `t3.utils.connman.ConnectionManagerLogger` (`.../utils/connman/ConnectionManagerLogger.java`) writes a tamper-evident, MD5-chained local `audit.log` file (path via `Paths3T.getPathCommonSettings("audit.log")`, 5MB rotation) recording only **Connection Manager** actions — New/Edit/Delete/Duplicate/Import connection or folder — with ISO timestamp, OS `user.name`, hostname, and SUCCESS/FAIL outcome. It is call-gated by `CustomInstallationSettings.shouldWriteAuditLog()` → registry key `WriteAuditLog`, default **off**, settable only via Windows Group Policy/registry or installer manifest (`utils/installation/CustomInstallationSettings.java:75`, wired at `utils/connman/ConnectionManager.java`, `GUIActionHandler.java`, `ConnectionInfoIO.java`, `ToUriDialog.java`). (2) `t3.auditlogging.AuditEventSender`/`AuditEvent`/`AuditRecord` (added 2026-06-03, commit `0a798b1d9cb`, ticket KONG-11032) is a fully-built HTTP sender that POSTs a rich audit event (actor id/email, resource, action, session, project id, source IP) to a 3T Access audit endpoint (`AccessManagerEndpointFinder.getAuditEndpoint()`) — but a repo-wide grep for `AuditEventSender` / `new AuditRecord(` shows **zero call sites anywhere in `product-suite/`**. It is unused scaffolding, not a shipped feature, and it requires the user to be logged into 3T Access (`AccessManager.getInstance().isLogged()`) to function at all — i.e. it is not a Desktop-IDE-native capability, it's a 3T-Access-dependent stub. |

Gated by `AppFeatures.ROLES_TAB`, available from `Edition.PROFESSIONAL` upward (same tier as users). |

## Undocumented capabilities found (new sub-feature ID candidates)

None of the mechanisms found above are wholly new capabilities outside the existing `GOV-*` ID set — they are refinements/corrections of existing IDs. One item worth flagging as a **documentation gap rather than a new ID**: the dual audit-logging architecture (local `ConnectionManagerLogger` file vs. unused `AuditEventSender` HTTP stub) is materially different from what `GOV-audit-log`'s one-line description implies, and probably deserves either a split into two IDs (`GOV-audit-log-local` for the shipped local mechanism, `GOV-audit-log-am` for the unshipped 3T-Access-bound sender) or a substantially rewritten description — see Confidence notes below.
