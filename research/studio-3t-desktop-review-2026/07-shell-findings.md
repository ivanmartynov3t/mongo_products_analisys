## Undocumented capabilities found (new sub-feature ID candidates)

1. **`SHELL-destructive-guard` — Destructive command detection and warning.** Dedicated class `t3/dataman/gui/intellishell/MongoDestructiveCommandChecker.java` (93 lines): a `DestructiveCommand` enum with 19 regex-matched patterns (`DROP_DATABASE`, `DROP_COLLECTION`, `DELETE_ONE`, `DELETE_MANY`, `REMOVE`, `DROP_INDEX(ES)`, `RENAME_COLLECTION_WITH_DROP`, `DROP_USER`/`DROP_ALL_USERS`, `DROP_ROLE`/`DROP_ALL_ROLES`, `DROP_VIEW`, `REPLACE_DOCUMENT`, `UPDATE_(MANY_)WITH_UNSET`, `FIND_ONE_AND_DELETE`, `FIND_AND_MODIFY_REMOVE`, `BULK_WRITE_DELETE`), scanning script text before execution and surfacing a "do not ask again"-capable warning dialog. Extensive, actively-maintained git history: commits `63de4f43b09` ("Alert for destructive queries in intellishell"), `cf2a3989d4d`, `209bfa21870` ("Handle more destructive commands"), `bce07925b6f`/`d7541b19948`/`8f7951549e5`/`72420e4ae9d` (settings relocated from IntelliShell-local toggle to the global Behavior preferences tab), through `2025.21.0` changelog entry "confirmation prompts added for destructive IntelliShell commands" (17-Nov-2025 era). This is a safety feature currently absent from the feature dictionary and matrix and should get its own sub-feature ID rather than being folded into `SHELL-modes`.
2. **`SHELL-result-tab-limit` — Result tab count limiting (default on).** `AppProperties.java:272,1429,1956,2064-2070,3530` — `shouldLimitNumberOfIntelliShellResultTabs` (default `true`), a dedicated user preference capping the number of concurrently open Query-Assist result tabs. Referenced in git history via `e4f6d64c8ff` "Refactored usage of shouldLimitNumberOfIntelliShellResultTabs". Should be documented as a constraint/preference under `SHELL-result-tabs`, and the preference's togglability called out explicitly.
3. **`SHELL-bookmarks` — Script bookmarks (separate from history).** `t3/dataman/gui/intellishell/ScriptBookmark.java` extends `AbstractBookmarkContainer<ScriptItem>` — a distinct, user-curated saved-script list alongside the auto-recorded `ScriptHistory`. Not mentioned anywhere in the current matrix/report, which only documents auto-saved history.
4. **`SHELL-oidc-auth` — OIDC authentication for shell connections (including device flow).** Multi-commit feature line: `727bc4a137d` ("Add support for IntelliShell connecting by OIDC"), `7f7cadccc46`/`874dcece285`/`36ebcd54a35` ("Oidc device flow, add support for MongoShell"), `44f8a8355e2` (May 2026, "Add support for oidc device flow when mongoshell starts and connect immediately") touching `MongoShell.java`, `AMongoShellHost.java`, `MongoshHost.java`, and a dedicated `OidcMongoshConnector.java`. Confirmed still being actively fixed in 2026 (release notes 2026.9.0, 2026.10.0 — OIDC/on-prem hostname and device-flow-plus-trusted-endpoint fixes). This is a real, non-trivial, currently-undocumented authentication capability specific to the shell connection path (as distinct from general connection-manager OIDC support, which may already be covered under F-CONN — cross-check recommended so it isn't double-counted or, conversely, dropped entirely).
5. **Stored JS: rename capability.** `StoredJSManagementController.java:137` `asyncRenameFunction` — the interface (and `MongoStoredJSManagementController.java`) explicitly support renaming a stored function, in addition to create/read/update/delete/exists-check. If Stored JS functions are to be covered under a `SHELL-*` or separate sub-feature ID (currently there does not appear to be a dedicated Stored-JS sub-feature ID in the F-SHELL dictionary section at all — worth confirming with the dictionary owner), rename should be included as a capability, and syntax validation via an ANTLR `JavaScriptLexer`/`JavaScriptParser` before save should also be noted (`MongoStoredJSManagementController.java`, method comment "Parse the JavaScript code given and report any errors"). **No "execute this stored function against the server" action was found** in `FunctionTab.java`/`StoredJSManager.java` — only editing operations; this should not be claimed if it isn't already.
6. **Shell startup animation / feature tour (cosmetic/onboarding, low documentation priority).** `ShellAnimator.java`/`ShellAnimations.java` (cosmetic terminal-like typing effect) and a referenced `t3.dataman.gui.featuretour.IntelliShellFeatureTour` (onboarding tour, not independently inspected). Noted for completeness; likely not worth a dedicated sub-feature ID, but flagging in case product docs describe an "IntelliShell tour" elsewhere.
