## Note on source layout

The task brief suggested `t3/dataman/mongodb/gui/screens/` or `t3/dataman/mongodb/gui/mapreduce/`. Neither path exists in the current checkout under that exact prefix. The real locations, confirmed via `grep -ril "aggregat"` / `grep -ril "pipeline"` from the `t3/` root:

- **Aggregation Pipeline Editor**: `t3/dataman/gui/screens/aggregate/` (25 files, ~13,100 lines). Key classes: `AggregationComposite.java` (4345 lines, main tab controller), `AggregationPipelineStage.java` (1446 lines, enum of stage types + JSON templates), `AggregationStageEditor.java` (1094 lines, per-stage editor UI), `AggregationStageTab.java` (1646 lines), `AggregationStageResults.java`, `AggregationOptionsDialog.java`, `PipelineFlow.java`, `PipelineOutput.java`, `AggregationParser.java`, `AggregationSaveMenuHandler.java`.

## Undocumented capabilities found (new sub-feature ID candidates)

- **AI-assisted pipeline generation in the Aggregation Editor** — `AggregationComposite.java` has `createAiHelper()` (line 771), `setAiHelperConnection()`, `applyAiHelperQuery`, `toggleAskAnAiHelper()`, a toolbar "AI Helper" item (line 1511), sharing an entry point (`updateQueryFromClipboardOrAIHelper()`) with clipboard paste. Confirmed in changelog: "AI Helper — Studio 3T now lets you generate MongoDB queries from natural-language questions, right where you work in the sidebar" (also referenced for the Collection Tab / IntelliShell). A `FeatureFlags.AI_HELPER_LEGACY` flag gates an older code path, suggesting this has gone through at least one redesign. **Recommendation**: this is an AI-Helper capability, not aggregation-specific tooling — it should be documented under F-AI with a cross-reference note added to the Aggregation feature-report ("AI Helper is also reachable from the Aggregation Editor toolbar"), rather than a new AGG-* ID, per the task brief's own guidance.
- **`$listSearchIndexes` / `$listSampledQueries` stage support** — both appear as first-class enum entries in `AggregationPipelineStage.java` (lines 462 and elsewhere) but are not called out anywhere in the current matrix's stage-count description. Covered by the corrected AGG-stage-count evidence above; no new ID needed, just richer detail in the matrix note.
- **Save Aggregation to a remote 3T Lens server** — git commit `f5c3fc7b562` (2026-05-12, KONG-10915) adds "Save Aggregation to Remote 3T Lens server" as a new save destination in `AggregationSaveMenuHandler.java`. This is a governance/3T Lens integration touchpoint from within the Aggregation Editor that isn't reflected in AGG-save-load's current description (which only mentions Query Manager and .js file). Recommend either extending AGG-save-load's detailed-behavior text or, if the 3T Lens integration is deep enough to warrant its own row, flagging it as a documentation gap to reconcile with F-GOV's 3T Lens coverage.

- **maxTimeMS** (referenced only in the dictionary description for AGG-pipeline-opts, not previously in the matrix): confirmed present only in the *parsing* path (`MongoUtils.buildAggregationOptionsFromDocument()`, line 531, used when importing a pipeline that already has an options document, e.g. a pasted mongosh script) — not present as an editable field in `AggregationOptionsDialog.java`, and not set by `AggregationComposite.buildAggregationOptions()` (the live-execution path, lines 3074-3091). Recommend the matrix describe maxTimeMS as "supported when present in an imported/pasted pipeline options document; no dedicated UI control to set it," rather than listing it alongside allowDiskUse/collation/index hint as an equivalent first-class option.
- **Absence claims that should be flagged, not silently treated as confirmed-absent forever**: `$searchMeta`, `$vectorSearch`, and chart-builder-from-pipeline-output were all zero-hit greps across the full repository at the time of this review (2026-07-31) — a reasonable basis for "absent," but should be re-checked on the next audit pass since these map to active MongoDB/Atlas feature areas Studio 3T could add at any time.
