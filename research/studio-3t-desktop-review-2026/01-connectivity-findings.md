## Note on source layout

The task brief's expected paths `dataman/mongodb/gui/connection/` and `dataman/gui/teamsharingtab/` do not exist in the current checkout. The real connectivity code lives at:

- Connection profile model, auth, TLS, proxy, pool params: `t3/utils/connman/` (module root: `product-suite/data-man-mongodb-ent/src/main/java/t3/`)
- Auth mechanism implementations: `t3/utils/connman/auth/`
- SSH tunnel core: `t3/utils/ssh/`
- Reusable SSH Profiles / SSH Credential Manager: `t3/dataman/gui/sshcredentialmanagement/`
- TLS certificate providers (OS trust store integration): `t3/utils/ssl/certificateprovider/`
- Proxy: `t3/utils/proxy/`
- Credential encryption: `t3/utils/security/`
- Team Sharing (cloud, invite-by-email folders): `t3/teamsharing/`
- Local file/Git-backed connection library sharing: `t3/localresourcessharing/` + `t3/teamsharing/ui/tree/`
- Access Manager (3T Access) connection-tree integration: referenced from `t3/teamsharing/ui/tree/MRTreeContentProvider.java` and related AM-restriction code (governance-adjacent; only the connection-tree-visibility slice is in scope here)
- Edition/feature gating: `t3/utils/AppFeatures.java` (flag catalog), `t3/utils/Edition.java` (per-edition flag sets)

All findings below cite real file paths under `/Users/ivan/Project/3t.tools.intellij/3t.tools/product-suite/data-man-mongodb-ent/src/main/java/t3/`.

**Edition-name correction (source of truth):** `utils/Edition.java` defines exactly five `Edition` enum values with their **actual display names**: `PROFESSIONAL`/`CORE`/`PRO` all display as **"Professional"**, `ROBO` displays as **"Community Edition"**, `FREE` displays as **"Free"**, `ENTERPRISE` displays as **"Ultimate"**. This resolves the current feature-report's "Exact edition tier names are unknown/unverified (pricing page returned 404)" open question for the tiers relevant to connectivity gating — Studio 3T does not have a separately named "Pro/Base" edition in code; `PRO` and `CORE` are code aliases that both resolve to the "Professional" display name and an identical feature set to `PROFESSIONAL`.

### Additional gating finding not tied to an existing row

- **`AppFeatures.MANAGE_UNRESTRICTED_NUMBER_OF_CONNECTIONS`** is declared in `utils/AppFeatures.java` and listed in **every** `Edition.java` tier including `FREE` and `ROBO` — but a repo-wide search found **no other usage of this flag** anywhere except its own declaration and the per-edition `EnumSet` listings (i.e., no `App.hasFeature(AppFeatures.MANAGE_UNRESTRICTED_NUMBER_OF_CONNECTIONS)` call site exists in current code). Historically, `ROBO-110: Add limit of loaded connections for free edition` (multiple commits, ~2 years old per git log ordering) added a stored-connection-count limit for Free edition. Current code suggests the flag exists but its enforcement call site could not be located in this pass — status: **unverified** whether a connection-count limit is still actively enforced for Free-tier users. Recommend a follow-up grep for the actual limit-check logic (likely a numeric constant rather than this flag) before asserting either way in the matrix.

## Undocumented capabilities found (new sub-feature ID candidates)

- **`CONN-session-restore`** — Session Restore: reopens all connections/tabs open at last shutdown, automatically, on next launch. `AppFeatures.SESSION_RESTORE` is defined in `utils/AppFeatures.java` and present in `PROFESSIONAL`-derived editions in `Edition.java` (not found in `ROBO`/`FREE` sets). Referenced from `utils/properties/v2/UserSettingsStore.java`, `utils/gui/dialogs/propertiesdialog/tabs/AppearanceTab.java` and `BehaviorTab.java` (user-facing toggle), `utils/shortcuts/ShortcutManager.java`/`ShortcutCategory.java`/`ShortcutAction.java` (has its own shortcut), `utils/swt/DTabFolder/DTabFolderComposite.java`. This is a real, user-visible, edition-gated capability with no corresponding sub-feature ID in the dictionary today. Suggested description: "Automatically reopen all connections and tabs that were open when the app was last closed; togglable in Behavior preferences." Suggested status: confirmed, Professional+ only.

- **`CONN-git-repo-sharing`** — Local file-system / Git-backed connection library. Distinct from `CONN-team-sharing` (which is Studio 3T's own cloud-mediated invite-by-email sharing): this is a **local folder of connection XML files that can optionally be a Git working tree**, with in-app Git actions. Evidence:
  - `t3/localresourcessharing/GitOperations.java` — thin wrapper around the `git` CLI: `hasRemote`, `hasUncommittedChanges` (`git status --porcelain`), `addRemote`, `fetch` (+ `countFetchedCommits`, comparing `HEAD..@{u}` or falling back to `FETCH_HEAD`), plus (per git log) push/pull/reset actions added in sibling commits (`KONG-10956: Add Git Push action`, `KONG-10957: create action git pull`, `KONG-10958: create action git fetch` / `git reset and sync`).
  - `t3/localresourcessharing/LocalFileLibraryTreeNode.java`, `LocalFileSystemManager.java` — represent/manage the local folder as a resource tree.
  - `t3/dataman/gui/sidebar/AddLocalGitRepositoryDialog.java` — UI to add a local Git repository as a connection-sharing source.
  - `t3/teamsharing/ui/tree/LocalRepoFetchBadge.java`, `t3/teamsharing/ui/tree/MRTree.java` (Git Push wiring) — UI badge showing fetched-but-unmerged commit count in the My Resources tree.
  - Git history: `KONG-10268` ("saved new connection info to repository as xml file"), `KONG-10270` (create/select local repository, add folders), `KONG-10336` ("added git feature flag"), `KONG-10343`/`KONG-10347` (repo tree menu items, icons), `KONG-10713` ("update connections in local repository on change"), `KONG-10767: Allow export on local host connections`, `KONG-10953: make localRepoConnectionInfos concurrent to fix intermittent crash saving connection as new in git repo`.
  - Changelog: "65: Improvement: Local File Support - Enable saving and loading MongoDB and SQL connections from the local file system (including Git-backed folders)."
  - This is a genuinely new, non-trivial capability (connection configs as version-controlled files, with push/pull/fetch/reset actions surfaced in the UI) that has no corresponding ID in the dictionary today — it is neither `CONN-team-sharing` (cloud) nor `CONN-portability` (one-shot JSON export/import); it's an ongoing, syncable, Git-native storage backend for shared connections. Suggested status: confirmed.

- **`CONN-access-manager-integration`** (borderline F-CONN/F-GOV; flagging here since it changes connection-tree behavior, with the deeper AM/RBAC semantics belonging to F-GOV) — 3T Access Manager-governed connections now surface directly inside the Connection Manager / My Resources sidebar as a distinct node type, with several UI restrictions applied automatically:
  - `t3/teamsharing/ui/tree/MRTreeContentProvider.java` — "Access Manager Resources" root node (`KONG-10734`).
  - Restrictions found via git log: block duplicate (`KONG-10763`), block export/"to URI" (`KONG-10752`/`KONG-4c09edf`), block edit options (`KONG-10762`), block drag-and-drop (`KONG-10764`), disable colors and quick-connect shortcut (`KONG-10774`), force read-only lock (`KONG-10832`, see `CONN-readonly-lock` row above), restrict copy/export per AM policy (`KONG-10838`).
  - `KONG-10880: add option to edit SSL and SSH settings for access manager connections` shows AM connections *can* still have their SSL/SSH settings edited (a later loosening of the initial full-lockdown).
  - This is a real and fairly extensive set of connection-tree behaviors (2026, ~10+ commits) with no corresponding sub-feature ID. Recommend either a new `CONN-access-manager-integration` ID scoped to "AM connections appear in the tree with restricted edit/export/duplicate/color/drag-drop, and forced read-only, per AM policy" — or, if the team prefers, fold a summary into `CONN-readonly-lock`'s row (force-lock) and add a one-line cross-reference to F-GOV for the rest. Flagging both options for the synthesis pass rather than deciding unilaterally, since it sits across two Feature IDs.
