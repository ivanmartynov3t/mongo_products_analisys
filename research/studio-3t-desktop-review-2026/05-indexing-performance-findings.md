## Note on source layout

The task brief's expected path `t3/dataman/mongodb/gui/{indexmanager,queryprofiler,statsview}` does not exist in the current checkout. The real locations are:

## Undocumented capabilities found (new sub-feature ID candidates)

Most "undocumented" capability in this feature area is *already present in the feature dictionary* but missing from the matrix (see the "not in matrix (dictionary-only)" rows above: `IDX-type-hashed`, `IDX-collation-opts`, `IDX-text-opts`, `IDX-geo-opts`, `IDX-advanced-opts`, `IDX-quick-actions`, `IDX-profiler-analysis`, `IDX-profiler-export`, `IDX-profiler-live`, `IDX-perf-insights`, `IDX-realtime-perf`, `IDX-stop-ops`). That is the headline finding for this feature area — 14 of the 26 dictionary sub-feature IDs for F-IDX have no row at all in `feature-matrix.md`, several of them (hashed index, full collation/text/geo options, currentOp+killOp real-time monitoring) representing real, shipped, non-trivial capability that a documentation consumer reading only the matrix would not know exists.

Two capabilities found in code with no matching dictionary ID at all:

- **Index Properties tab (`statsview/IndexPropertiesTab.java`)** — a dedicated read-only per-index stats/diagnostic view (distinct from the editable Index Manager), opened via right-click → "Show Properties" on an index in the connection tree, showing raw index property/size output. No existing `IDX-*` ID covers this specific diagnostic view. Recommend either folding it into `IDX-inventory`'s description or adding a new ID, e.g. `IDX-properties-view`.
- **Read-only-connection restrictions applied to Index Manager** — recent commits `a06aae4af00` (KONG-10731, "Apply connection read only restrictions to Index Manager") and `d7f4738d602` (KONG-10822, "Disable shortcuts from firing in Index Manager when connection is read only") add a safety behavior: when a connection is marked read-only, Index Manager actions (and their keyboard shortcuts) are disabled. This is a cross-cutting product safety feature worth a one-line mention in the feature-report's constraints section, though it likely doesn't warrant its own sub-feature ID (it is a repeat of a pattern applied across other tools too).
