## Headline finding

The repo's own gap-analysis and low-level comparison currently state Studio 3T Desktop has **"Not supported (no validator creation/deploy)"** for the entire MongoDB collection-validation cluster. This is **incorrect**. Studio 3T Desktop source code contains a complete, mature validator authoring/deployment feature: a dedicated "Add Validator" tree action, an "Edit Validator" dialog with a JSON editor plus Validation Level/Action dropdowns, a "Validator" tab in the Add Collection dialog, a JSON-validity check button, and a `collMod`-based deploy path. This has existed for years (the changelog shows validator-related entries as far back as 2020) and is unrelated to the still-genuinely-missing tree-based JSON Schema editor / visual ERD canvas cluster, which this audit independently re-confirms as absent.

**Net correction: 4 of the 13 items (`SCHEMA-validation-model`, `SCHEMA-validation-strictness`, `SCHEMA-validation-ui`, `SCHEMA-deploy-validator`) are false negatives and should be reclassified from "confirmed absent" to "confirmed" (implemented) for Studio 3T Desktop.** The remaining 9 — the entire visual-ERD/canvas cluster (5 IDs) plus the geo-analysis ID plus the tree-based JSON-Schema-editor cluster (`SCHEMA-json-editor`, `SCHEMA-bson-types`, `SCHEMA-field-constraints`, 3 IDs) — are genuinely absent and the claim holds for those.

This also means the framing in the gap-analysis report's "Takeaway" line — *"the entire 3T product family's one confirmed capability gap versus competitors is schema validation authoring/deployment and the visual ERD / JSON-schema-editor cluster"* — is half wrong: **validation authoring/deployment is not a gap.** Only the tree-based JSON Schema editor and visual ERD/canvas capabilities remain a real, confirmed gap. The `PROP-schema-erd-cluster` proposal in `feature-dictionary.md` (tagged "🔗 13 IDs", Deferred) should be corrected to reference only the 9 still-absent IDs, not all 13.

Additionally, `SCHEMA-validation-limits` — listed as "unverified" in the companion gap-analysis report, not among the 13 — should be upgraded to **confirmed**: the code enforces MongoDB ≥ 3.6, excludes `admin`/`local`/`config` databases, and excludes `system.*` collections (`ValidatorInfo.java` lines 23–38, 81–87).

## Undocumented capabilities found (new sub-feature ID candidates)

No wholly new capability requiring a fresh sub-feature ID was found beyond what's already named in the dictionary. The findings above are corrections to existing IDs' status, not new capabilities. One nuance worth capturing in the eventual feature-matrix rewrite rather than as a new ID: Studio 3T lets a validator be attached **at collection-creation time** via a "Validator" tab in `AddCollectionDialog` (in addition to adding/editing one on an existing collection) — this is a detail of `SCHEMA-validation-ui`'s existing scope, not a separate capability.

- `git log --since="24 months ago"` against `schemaexplorer/` (6 commits) and against `dataman/gui/collection/EditValidatorDialog.java` / `ValidatorInfo.java` / `ValidationParams.java` (1 commit) shows **no feature-level changes** in the last 24 months — every commit touching these paths is a pure internal refactor (e.g. `KONG-10817: Split SWT Methods from StringHelpers and DateUtils`, `KONG-10814: Extract COLLECTION_TYPE Enum from DatabaseInfoContainer`, `KONG-10803: Refactor`). No behavioral schema/validation changes landed in this window.
- `release/studio-3t/changelog.txt` was searched for `schema|validat|jsonSchema` (case-insensitive) across its full history. All validator/JSON-Schema-specific entries are old (2020–2022), e.g.:
  - `2022.5.0 (19-May-2022)`: "Improved: Schema Validators - Schema Validations are now copied when a collection or database with validations attached to them are copied." — confirms the validator feature was already mature and actively maintained years before this window, and that "copy collection" respects validators (also visible in code: `AppController.java` `hasDocumentValidator`, `copyDocumentValidator` logic around lines 4612–5109).
  - `2020.7.0 (27-Jul-2020)`: "Fixed: JSON Validator - Fixed the width of the 'Edit Validator' dialog..."
  - `2020.10.0 (09-Dec-2020)`: "New: Reschema - Move collections to a new schema. (Pro and Enterprise only)" — this is the unrelated SQL-Tools "Reschema" restructuring feature (`dataman/gui/reschema/`), not F-SCHEMA's validator/JSON-Schema cluster; flagged here only to avoid confusing the two in future passes.
- Within the last 24 months (2024-07 onward), the only schema-adjacent changelog entries are AI-Helper-related, not F-SCHEMA UI changes: `2026.7.0` ("AI Helper Tool - The AI Helper now has access to a schema analysis tool") and `2026.9.0` ("AI Tools ... analyze-schema ... also available through a local MCP"). These belong to F-AI (`AI-schema-aware`/`AI-003`/local MCP toolset), not to F-SCHEMA itself, and are already tracked there.
- No release-notes evidence was found of any changes to the visual-ERD/canvas cluster or a tree-based JSON Schema editor at any point in the changelog's full history (not just the 24-month window) — consistent with these never having been built.

## Confidence / spot-check notes

- High confidence on the validator-authoring correction: three independent code paths converge (dialog UI in `EditValidatorDialog.java`/`AddCollectionDialog.java`, tree-menu wiring in `OpenConnectionsTree.java`/`ShellMenu.java`, and controller/driver plumbing in `AppController.java`/`ValidatorInfo.java`), plus a changelog entry from 2022 independently corroborating the feature's existence and age.
- High confidence on the absence of the tree-based JSON Schema editor and the ERD/canvas cluster: an exhaustive `grep` for `jsonSchema`, `diagram`, `canvas`, `erd`, and `geo` across the entire `t3` source tree (not just `schemaexplorer/`) turned up no relevant hits beyond coincidental substring matches (JavaFX `geometry`/`Canvas` classes, the unrelated Explain Plan `Canvas.java`).
- Not independently re-verified in this pass (out of scope per the task's read-only source focus, and not needed to resolve the "13 confirmed-absent" question): whether MongoDB Compass's or VisuaLeaf's validation-UI feature-matrix entries (cited as the source of Studio 3T's "Missing" status in the comparison report) are themselves accurate — this audit only checked the Studio 3T Desktop side of the comparison.
- `SCHEMA-file-export` ("Export analyzed schema to standard file formats (JSON Schema, etc.)") was checked opportunistically: `schemaexplorer/documentation/` only contains `DocxDocumentationWriter` and `CsvDocumentation` — no JSON/JSON-Schema export writer exists. - The reschema (`SQL-reschema`, `dataman/gui/reschema/`) module was located and briefly inspected to rule out confusion with F-SCHEMA's validation cluster — it is schema-restructuring for SQL migration purposes and is correctly out of scope for this F-SCHEMA audit.
