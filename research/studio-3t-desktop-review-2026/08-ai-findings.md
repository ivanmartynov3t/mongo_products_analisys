## LLM provider support re-check (which providers are actually integrated, with evidence)

- **Anthropic Claude** — confirmed, integrated **directly via the official Anthropic Java SDK** bundled in this repo at `3t.tools/third-party/anthropic-sdk-java-3t/` (imports `com.anthropic.client.AnthropicClient`, `com.anthropic.client.okhttp.AnthropicOkHttpClient`, `com.anthropic.models.messages.*` in `t3/dataman/gui/chatGPT/manager/AiHelperClientImpl.java`), confirming the task brief's hypothesis that SDK presence is a strong signal — Claude is a first-class, directly-integrated backend, not an afterthought. Streaming responses use `claudeClient.messages().createStreaming(params)` with a `MessageAccumulator`. A **second, newer client path** exists for the "AI Helper Plus" (tool-calling/agentic) mode: `AiHelperPlusClientImpl.java` uses **LangChain4j's** `dev.langchain4j.model.anthropic.AnthropicChatModel`/`AnthropicStreamingChatModel` wrapper instead of the raw SDK, and explicitly enables **Anthropic prompt caching** (`.cacheTools(true).cacheSystemMessages(true)`) — corroborated by changelog line 4 (2026.12.0: *"Improved prompt structuring to increase the Anthropic prompt cache hit rate"*) and git commit `80dab9c4ff4` ("KONG-11117: Cache Anthropic system prompt and tool definitions").
- **OpenAI** — confirmed, via the **Azure OpenAI Java SDK** (`com.azure.ai.openai.OpenAIClient`), used for both direct OpenAI and Azure OpenAI (Azure's SDK supports both endpoints). LangChain4j's `OpenAiChatModel` is used in the AI Helper Plus path. Commit `ae5c6187cc9` ("Disable OpenAI parallel tool calls without reflection") and changelog note "New: AI Tools" show OpenAI is a full tool-calling backend, not text-only.
- **Azure OpenAI** — confirmed as its own distinct backend (`AzureAiHelperConfig.java`, `AzureAIConfigComposite.java`), requiring API key + deployment name + endpoint URL as documented; LangChain4j `AzureOpenAiChatModel` used in the Plus path.
- **No other providers found.** A targeted whole-tree grep for Gemini/Llama/Ollama/local-model/custom-endpoint strings returned zero hits outside the three providers above. There is, however, a related but architecturally distinct integration: Studio 3T's own AI Helper Plus agent can additionally use **MongoDB Inc.'s official `mongodb-mcp-server`** npm package as an extra *tool source* (not an LLM provider) — see "Undocumented capabilities" below.
- **API key storage** — confirmed encrypted at rest, per-provider, not shared with any 3T-operated proxy: `t3/utils/properties/v2/AISettingsStore.java` stores `openAiSettingsV2` / `claudeAiSettings` / `azureAiSettingsV2` as JSON with each API key stored as `{"encryptedPassword": base64, "iv": base64}` (`t3.utils.security.password.Password` / `t3.utils.security.EncryptionManager`). The only outbound intermediary is an optional user-configured **corporate network proxy** (`ProxyOptionsFactory`) — a pass-through, not a data relay — consistent with the doc's implicit "direct to vendor" model and with changelog entries about Claude-via-proxy support (line 111: *"Added support for connecting to Anthropic Claude AI via proxy"*).
- **Multiple named configs — correction.** The doc dictionary's `AI-multi-config`/`AI-named-configs` concept is only **partially true in Studio 3T**: each of the three providers has its own persistently-stored credentials (switching the active provider dropdown does not erase the other two providers' saved keys/settings), but there is **no arbitrary user-named multi-config system** (e.g., "Claude — Team A key" and "Claude — Team B key" as two separate saved profiles for the same provider) — there is exactly one active credential set per provider, selected via a single "which provider is active" dropdown plus one global enable/disable toggle. Recommend marking `AI-multi-config`/`AI-named-configs` as **partial**, not confirmed, for Studio 3T if/when those generic sub-feature IDs are ever scored against it.
- **Privacy/sample-data toggle — likely absent, contradicting the dictionary's generic `AI-privacy`/`AI-sample-data-toggle` concepts if ever scored against Studio 3T.** Targeted grep for `sendSampleData`, `includeSamples`, `privacyMode`, "schema only", "sample document(s)" near the AI Helper code found no such toggle. What sample-scanning does happen (`AiHelperUtils.getScanSourceScanConfig()`, `ScanMode.FIRST`, `NumDocsToScan(50)`) appears to be schema-shape metadata construction, not a user-facing "send samples vs. schema-only" switch — this exact detail (does field-level metadata include representative values or only field name + BSON type?) was **not fully traced end-to-end** and should be marked unverified rather than asserted either way.

## Undocumented capabilities found (new sub-feature ID candidates)

1. **AI Helper mismatch/guard-rail layer for "apply to editor"** (candidate ID e.g. `AI-apply-guardrails`) — a materially real safety layer contradicting the current doc's "no validation" framing under AI-004: type-compatibility routing (`GlobalAiHelperChangeActionCoordinator`/`GlobalAiHelperChangeActionDecision`), source-collection-mismatch confirmation (`GlobalAiHelperFindCollectionMismatchPolicy`), unsaved-changes protection before overwrite (`GlobalAiHelperInPlaceGuardPolicy`), and syntactic query-parse validation (`FindCommandParser`) with error dialogs on failure. Evidence: `t3/dataman/gui/chatGPT/ui/GlobalAiHelperChangeActionCoordinator.java`, `GlobalAiHelperFindCollectionMismatchPolicy.java`, `GlobalAiHelperInPlaceGuardPolicy.java`, `GlobalAiHelperMismatchMessageBuilder.java`.

2. **AI Helper Plus (agentic tool-calling mode)** (candidate ID e.g. `AI-helper-plus-agent`) — a distinct, more advanced mode gated by `FeatureFlags.AI_HELPER_PLUS` (default **false** — pre-release/experimental as of the commits examined) and `AppFeatures.AI_HELPER_PLUS` license entry, backed by LangChain4j (`AiHelperPlusClientImpl.java`) with a dedicated system prompt (`PLUS_CONTEXT`) instructing the model to "review the entire conversation history," a bounded chat memory (`MessageWindowChatMemory.withMaxMessages(10)`), tool-calling against Studio 3T's own internal tool set **plus** an externally-installed official MongoDB MCP server subprocess (see #3), and mid-execution tool-cancellation support (git commits `d6d07a9ba27`, `fd9b1e9918f`... specifically `fd8c3d2dd76` "Cancel running MCP tools when the AI Helper is stopped", `5274b099a61` "Finalize AI Helper mid-tool cancellation"). This is materially different from, and more capable than, the plain NL-to-query flow documented under AI-003, and is entirely undocumented in the current feature-matrix/report.

3. **Bundled/offline-installed official MongoDB `mongodb-mcp-server` as an internal tool source** (candidate ID e.g. `AI-bundled-mongo-mcp-client`) — `t3/mcpserversupport/**` is **not** related to the in-process `t3.mcp` server (that package is a red herring relative to its name); it installs and runs MongoDB Inc.'s own official `mongodb-mcp-server` npm package offline (bundled Node runtime, `win-x64`/`darwin-arm64` only) as a **stdio MCP client subprocess** consumed by Studio 3T's own AI Helper Plus agent via LangChain4j (`MongoMcpClientRegistry.java`, `dev.langchain4j.mcp.client.DefaultMcpClient` + `StdioMcpTransport`), always forced read-only (`MDB_MCP_READ_ONLY=true` environment variable, and `--readOnly` flag on the `npx` fallback path for unsupported platforms, pinned to `mongodb-mcp-server@1.2.0`). Gated by `MCPInstallerSupport.mcpSupportEnabled()` → `FeatureFlags.AI_HELPER_PLUS`. This means Studio 3T's AI agent can draw on **two separate MongoDB tool sources simultaneously** — its own native tool set (`Studio3TToolService`) and the official community MCP server — a nuance entirely absent from current docs. No evidence this package writes to external MCP client config files (e.g., Claude Desktop's `claude_desktop_config.json`) — it is one-directional (Studio 3T consuming an external tool), not Studio-3T-registering-itself-with-other-apps.

4. **`list_connected_tabs` / Global Tab Context Registry** (candidate ID e.g. `AI-tab-context-awareness`) — an internal-only (`@InternalTool`, not exposed to external MCP clients) capability giving the in-app AI agent live awareness of currently open Studio 3T tabs (IntelliShell, Aggregation, Collection View — deliberately scoped, per commit `b9d14ac317a` "limit list_connected_tabs to IntelliShell, Aggregation, and Collection View tabs"), including database/collection name per tab, kept in sync with tab rename/close events (`TabContextRegistry.java`, `ActiveTabTracker.java`). This is a genuine schema/context-awareness capability beyond what AI-003's current "schema-aware" note describes, and is worth its own line — it is what lets the Global AI Helper know "the user is currently looking at collection X" without the user re-stating it.

5. **AI Helper response chart rendering** (candidate ID e.g. `AI-chart-rendering`) — `t3/dataman/gui/chatGPT/response/rendering/AiHelperChartRenderer.java` renders **pie, bar, horizontal-bar, and stacked-bar charts** from AI responses using an embedded JavaFX canvas inside the SWT chat view. The AI is instructed via a `CHART_FORMAT_SPEC` prompt fragment to emit fenced ` ```chart ` JSON blocks (`{"type":"pie|bar|horizontalBar|stackedBar","title":"...","data":[...]}`), capped at 4 charts per response, tied specifically to schema-analysis/report requests (i.e., pairs naturally with the `analyze_schema` MCP tool). This is a completely undocumented capability — the current doc describes AI Helper purely as a text/query generator, with no mention of any visualization output.

6. **Conversation auto-titling via LLM** (candidate ID e.g. `AI-auto-title`, or fold into AI-005) — the Global AI Helper generates a short conversation title automatically via a dedicated LLM call after the first user message, with retry and fallback logic (commits `e4c771f9057`, `6be52a92eee`). Minor but real, undocumented UX capability supporting the new multi-conversation feature (finding #2 in the status table above).

7. **Telemetry for AI Helper usage** (worth a one-line mention, not necessarily a new sub-feature ID) — `GlobalAiHelperErrorClassifier.java` classifies LLM API errors into PII-free categories (AUTH/RATE_LIMIT/SERVER_ERROR/CLIENT_ERROR/SSL/TIMEOUT/NETWORK/CONFIG/UNKNOWN) explicitly to avoid leaking raw messages/URLs/hostnames into telemetry; separate commits add telemetry events for MCP tool usage (`f8071d958fc` "add telemetry for mcp server usage"), tool execution (`ac97e700bb3`), and conversation lifecycle events (new/switch/rename/delete, commits under `KONG-11100`). Signals a mature, privacy-conscious telemetry layer around AI features that current docs don't mention at all (may be more relevant to a future F-GOV/telemetry review than F-AI itself, but flagging here since it was found in this pass).
