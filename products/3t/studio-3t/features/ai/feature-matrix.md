### Scope note — generic F-AI dictionary IDs not confirmed for Studio 3T

The 2026-07-31 source-code audit checked three **generic** sub-feature IDs from the feature dictionary's F-AI list that are not currently referenced as rows in this matrix. Per the audit, Studio 3T Desktop does **not** clearly implement these in the form the generic ID describes, and if they are ever scored against Studio 3T they should be marked **partial or absent**, not confirmed:

- **`AI-privacy`** — no schema-only-vs-schema+samples privacy toggle found (targeted grep for `sendSampleData`, `includeSamples`, `privacyMode`, "schema only" near the AI Helper code returned no hits). What sample-scanning does happen (`AiHelperUtils.getScanSourceScanConfig()`, `ScanMode.FIRST`, 50 docs) is schema-shape metadata construction, not a user-facing toggle — **absent as documented, one detail (samples vs. schema-only in the field-level metadata sent to the LLM) left unverified**.
- **`AI-sample-data-toggle`** — same finding as `AI-privacy` above — **absent as documented**.
- **`AI-multi-config` / `AI-named-configs`** — **partial**: each of the three providers (Azure/OpenAI/Anthropic) has its own persistently-stored credentials, but there is no arbitrary user-named multi-config system (e.g., two separately saved profiles for the same provider) — exactly one active credential set per provider, selected via a single active-provider dropdown plus one global enable/disable toggle.

Source: S2 (see findings "LLM provider support re-check," final two bullets).
