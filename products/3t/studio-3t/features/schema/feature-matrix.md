## Capability matrix

| Capability ID | Capability | Current support | Detailed behavior | Constraints / prerequisites | Roadmap status | Sources | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SCHEMA-sampling | Sample configuration | Supported | Sample mode: Random, First, Last, All. Configurable sample document count. "Omit individual array elements" checkbox (default: on — avoids inflating element-level statistics). Query criteria filter on sample (analyze a subset matching a query). | "All" mode on large collections is resource-intensive and may time out. | confirmed | S1 | All editions. |
| SCHEMA-field-prob | Schema tree — field probability | Supported | All discovered fields displayed with probability as a percentage of sampled documents containing that field. Surfaces sparse and inconsistently-present fields at a glance. | Probability is relative to sample size, not the full collection, unless mode = All. | confirmed | S1 | All editions. |
| SCHEMA-type-prob | Schema tree — per-field type probabilities | Supported | Each field shows all discovered BSON types with individual type probabilities (e.g., String 80%, Null 15%, Int32 5%). Reveals polymorphic fields that may cause application type errors. | Type probabilities are relative to documents in the sample containing that field. | confirmed | S1 | All editions. |
| SCHEMA-explore-docs | Right-click explore on schema fields | Supported | Right-click any field in the schema tree: "Explore documents containing selected field" or "Explore documents not containing selected field" — opens Collection Tab with the corresponding query pre-built ({field: {$exists: true/false}}). | Requires an open Collection Tab connection. | confirmed | S1 | All editions. |
| SCHEMA-histogram | Value Histogram (numeric fields) | Supported | Frequency histogram of most common numeric values in the sample. Surfaces value distribution and outlier spikes. | Histogram represents sample; rare values in the full collection may not appear. | confirmed | S1 | All editions. |
| SCHEMA-top-values | Top Values chart (string and mixed fields) | Supported | Frequency chart of top string values in the sample. Surfaces high-cardinality vs low-cardinality fields; reveals anomalies like unexpected null strings or typos. | Limited to top N values — long tail not visible in chart. | confirmed | S1 | All editions. |
| SCHEMA-date-dist | Date distribution visualizations | Supported | Date fields show four distribution breakdowns: hourly, daily, monthly, weekly, and all-time. Useful for time-series density analysis and detecting ingestion gaps. | Only available for fields with confirmed Date BSON type. | confirmed | S1 | All editions. |
| SCHEMA-stats-notes | Statistics and Comments tabs | Supported | Statistics tab shows numeric statistics per field. Comments tab allows annotating fields with notes (stored locally in Studio 3T). | Comments are not stored in MongoDB; they are local to the Studio 3T installation. | confirmed | S1 | All editions. |
| SCHEMA-doc-export | Documentation export | Supported | "Generate documentation" button exports schema documentation to Word (.docx) or CSV. Includes field names, types, probabilities, and statistics. | Requires write access to the target file system location. | confirmed | S1 | All editions. |
| SCHEMA-rename-discover | Rename-on-discover workflow | Supported | Right-click outlier field variant in schema tree → "Explore documents containing selected field" → right-click a value in result → "Rename Field" → "All documents in collection". Enables bulk field rename triggered directly from schema analysis. | Rename Field is a write operation; requires write access to the collection. | confirmed | S1 | All editions. |
| SCHEMA-view-editor | View Editor — db.createView() | Supported | Visual pipeline builder (same UI as Aggregation Editor stages) wrapped in a db.createView() call. $match stage pre-added. Any further aggregation stages can be added. | Requires MongoDB ≥ 3.4. Requires write access to the database. | confirmed | S2 | All editions. |
| SCHEMA-view-from-sql | View creation from SQL Query or Aggregation Editor | Supported | Create view from SQL Query via Query Code tab → paste pipeline. Create from Aggregation Editor via Save → "Create view from aggregate query". Both paths share the same View Editor. | SQL Query creation path requires Pro/Base+ edition. | confirmed | S2 | View Editor: all editions. SQL path: Pro/Base+. |
| SCHEMA-views-tree | Views in Connection Tree | Supported | Created views appear under the source database in the Connection Tree in a dedicated "Views" folder. Views are first-class queryable objects in Studio 3T (Collection Tab, Export, etc.). | Views reflect the pipeline definition; query performance depends on the underlying collection's indexes. | confirmed | S2 | All editions. |
| SCHEMA-validation-model | Validation rule model | Supported | Right-click a collection → "Add Validator" opens `EditValidatorDialog`, a free-form JSON editor for the validator document. Accepts either `$jsonSchema` or query-operator-style rules (it is a generic JSON/BSON document editor, not restricted to one syntax). Backed by `ValidatorInfo` (validator/validationLevel/validationAction model over the driver's `ValidationOptions`). | Corrects the prior "Not supported" status, which was a documentation gap, not a product gap. | confirmed | S3 | Previously misdocumented as absent; see findings. |
| SCHEMA-validation-strictness | Validation strictness | Supported | `ValidationParams` defines `VALIDATION_LEVELS = {off, strict, moderate}` and `VALIDATION_ACTIONS = {error, warn}`, wired into `EditValidatorDialog`'s Validation Level/Action combo boxes and persisted in `saveDialogState()`. | Corrects the prior "Not supported" status. | confirmed | S3 | Previously misdocumented as absent; see findings. |
| SCHEMA-validation-ui | Validation UI workflows | Supported (partial vs. competitors) | `AppWindow.addValidator()`: right-click a collection in the tree → "Add Validator" → existing validator fetched via `controller.getValidator()` → `EditValidatorDialog` opens → OK calls `controller.addValidator()`. Tree/menu wiring in `OpenConnectionsTree.java` and `ShellMenu.java`. A "Validator" tab is also present in `AddCollectionDialog` at collection-creation time. A "Validate JSON" button (`validateValidatorJson()`) checks JSON syntax before save. | Narrower than VisuaLeaf's described add/edit/generate/preview/apply flow: no distinct "Generate" step (auto-derive a validator from Schema Explorer results) and no "Preview" step separate from the JSON-syntax check. Real add/edit/deploy workflow is present. | confirmed | S3 | Previously misdocumented as absent; see findings. |
| SCHEMA-deploy-validator | Deploy validator | Supported | `AppController.addValidator()` builds a `collMod` command with `validator`, `validationLevel`, `validationAction` fields and runs it against the live collection via `database.runCommand(collMod)`. Validators are also copied when a collection or database is copied (since release 2022.5.0). | Corrects the prior "Not supported" status. | confirmed | S3 | Previously misdocumented as absent; see findings. |
| SCHEMA-validation-limits | Validation limits | Supported | `ValidatorInfo.isDocumentValidatorSupported()` enforces MongoDB ≥ 3.6 and disallows validators against the `admin`, `local`, `config` databases and any `system.*` collection. | Code-enforced scope limits, not merely documented ones. | confirmed | S3 | Previously "unverified"; upgraded to confirmed per findings. |
| SCHEMA-json-editor | JSON schema editor | Not supported | The only validator-authoring surface (`EditValidatorDialog`) is a plain syntax-highlighted JSON text editor (`EditorLanguage.JAVA_JSON`), not a tree UI. No expand/collapse tree, no per-node Add Field/Child/Delete/Duplicate actions, no drag-to-reorder, no View/Edit mode toggle. No code references `$jsonSchema` structurally anywhere in the source tree. | Distinct from `SCHEMA-validation-model`/`-ui`, which cover validator authoring/deploy and are confirmed. | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-bson-types | BSON type coverage | Not supported | No structured per-type schema-building UI exists (see SCHEMA-json-editor). BSON-type coverage for a hand-typed `$jsonSchema` document is limited only by what the user types, not by any dedicated UI surface. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-field-constraints | Field constraints | Not supported | No minLength/maxLength/pattern/min/max constraint widgets exist; only free-text JSON entry in `EditValidatorDialog`. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-geo-analysis | Geo schema analysis | Not supported | No map-backed field analysis or interactive geo filter drawing exists. `grep` hits under `schemaexplorer/` are coincidental `javafx.geometry.*` import matches only. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-designer-canvas | Visual canvas | Not supported | No canvas, diagram, or ERD-related class exists under `schemaexplorer/` or `dataman/gui/collection/`. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-designer-auto | Auto-generate diagram | Not supported | Depends on `SCHEMA-designer-canvas`, which does not exist. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-designer-links | Relationship detection | Not supported | Depends on `SCHEMA-designer-canvas`, which does not exist. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-designer-color | Color coding (canvas) | Not supported | Depends on `SCHEMA-designer-canvas`, which does not exist. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
| SCHEMA-designer-portability | Diagram portability | Not supported | Depends on `SCHEMA-designer-canvas`, which does not exist. | — | confirmed absent | S3 | No code found; re-confirmed by audit. |
