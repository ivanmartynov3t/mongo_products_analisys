## Confirmed-absent capabilities without a dedicated sub-feature ID

These were explicitly checked by the 2026-07-31 audit and confirmed absent, but do not warrant new `SCHED-*` IDs (they fall under the existing `SCHED-actions`/`SCHED-task-types` scope rather than being distinct capabilities):

- **Task dependency-chaining**: no "depend"/"chain"/"trigger" references exist anywhere in `t3/tasks`. `Task.java` carries an explicit architecture comment that a task can have only one schedule ("a second schedule will require a separate copy of the task"), consistent with no chaining/triggering model.
- **Dedicated task-template mechanism**: tasks are stored as individual `.task` zip files (XStream-serialized) under `<settings>/tasks/`. `TaskFileManager.duplicateTask()` deep-copies a task and resets its schedule to null — a "clone as template" workflow exists implicitly via Duplicate, but there is no separate first-class "template" concept (naming, library, or variable-substitution mechanism).
