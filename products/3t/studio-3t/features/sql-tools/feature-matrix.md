| Capability ID | Capability | Current support | Detailed behavior | Constraints / prerequisites | Roadmap status | Sources | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SQL-expressions | SQL Query — supported expressions | Supported (Pro/Base+) | **Dialect**: the SQL Query tool is not MySQL syntax — it is parsed by an ANTLR4-based grammar that is a heavily 3T-modified fork of the public `sqlite-parser` grammar (`SQLiteParser.g4`/`SQLiteLexer.g4`), translated into MongoDB aggregation pipelines by `SQLiteExpressionVisitor`/`SQLiteSelectVisitor` (`t3/utils/mongodb/sql/`). Confirmed syntax: SELECT *, SELECT DISTINCT, column projection, WHERE with JSON object literals, dotted name access for nested fields, backtick or [ ] quoting for field names, AND/OR/NOT, ORDER BY (asc/desc), GROUP BY + HAVING, COUNT, SUM, AVG, MIN, MAX, LIMIT, OFFSET, LIKE + wildcards (%, _) with optional ESCAPE, IN (literal list only), BETWEEN / NOT BETWEEN, boolean literals, BSON type constructors (ObjectId, NumberDecimal, BinData, ISODate, Date, etc.), array field access. **Also supported but previously undocumented**: GLOB and REGEXP predicate operators (with optional ESCAPE), alongside LIKE; STDEV/STDEVP aggregate functions (map to `$stdDevSamp`/`$stdDevPop`); RAND/RANDINT/RANDDOUBLE random-value functions; additional BSON constructors MaxKey(), MinKey(), Symbol(...), Undefined()/BsonUndefined(), NumberLong(...). **Confirmed absent** (not silently missing — explicitly unsupported by the grammar/visitor): `CASE...WHEN...END`, `CAST(...AS...)`, `COLLATE`, `RAISE`, `MATCH`, any subquery form (scalar, `IN (SELECT ...)`, `EXISTS (SELECT ...)`), `WITH`/CTEs, and compound `SELECT ... UNION/INTERSECT/EXCEPT`. **Unverified/likely inaccurate**: `LUUID` as a BSON WHERE-clause constructor — no `LUUID` entry exists in `ExpressionFunctionCalls`'s function table; LUUID handling elsewhere in the codebase is for document field display/editing, not SQL WHERE clauses — flag for removal or re-verification rather than repeating as confirmed. **Confirmed absent**: no BI/ODBC/JDBC-server capability exists exposing MongoDB collections as a SQL data source to external tools (Tableau, Power BI, etc.) — searched and not found anywhere in the product source. | Requires Pro/Base+ edition. ORDER BY on DISTINCT queries: ORDER BY field must appear in SELECT DISTINCT list. IN only accepts a literal value list, not a subquery. | confirmed | S1, S4 | Pro/Base+ only. Dialect and undocumented/absent syntax corrected 2026-07-31 per source-code audit — see findings. |
| SQL-join-mapping | SQL Query — joins | Supported (Pro/Base+), with a real limitation | INNER JOIN (translates to $lookup), LEFT JOIN (translates to $lookup), CROSS JOIN (and comma join syntax), self-join via aliases, multiple chained joins in a single query. GROUP BY + HAVING + aggregate functions work across joined collections. Projection requires collection-qualified field names in join queries. **Correction**: there is no visual/drag-and-drop JOIN-condition mapping editor — joins are authored purely as SQL text (typed `JOIN ... ON ...` clauses parsed by the SQL grammar), same as any other SQL clause; no such visual mapping widget exists under `dataman/gui/sqltab/` (a visual relationship-mapping UI does exist, but it belongs to the separate SQL migration wizards, not the query tool). **Real limitation**: `JoinExpressionVisitor` supports only a single equality comparison per JOIN clause (e.g. `t1.a = t2.b`); compound, AND-ed multi-field join conditions are not supported and throw `NotImplementedException` at query time. | Requires Pro/Base+ edition. Join performance depends on collection size and available indexes; no automatic join optimization is noted. JOIN ON supports only one equality comparison — compound (AND-ed) join conditions are not supported. | confirmed | S1, S4 | Pro/Base+ only. Description corrected 2026-07-31 — see findings. |
| SQL-code-gen | SQL Query — code generation | Supported (Pro/Base+) | Query Code tab generates: JavaScript (Node.js), Java 2.x driver API, Java 3.x driver API, Java 4.x driver API (separate sub-tabs), C#, Python, PHP, Ruby, MongoDB Shell (mongosh syntax). "Open in IntelliShell" button for MongoDB Shell target. Result editing: inline double-click; read-only padlock per tab or per connection. | Generated code reflects the aggregation pipeline that the SQL query translates to. | confirmed | S1 | Pro/Base+ only. |
| SQL-migration | SQL → MongoDB migration — setup | Supported (Pro/Base+) | Multiple import units per migration job (configurable to run in parallel). Source per unit: full SQL table (all rows) or custom SQL query (supports filter, JOIN, UNION). Supported SQL sources: MySQL, PostgreSQL, Oracle, SQL Server (JDBC-based). | Requires Pro/Base+ edition. JDBC driver for source database must be accessible. | confirmed | S2 | Pro/Base+ only. |
| SQL-migration-schema | SQL → MongoDB migration — schema manipulation | Supported (Pro/Base+) | Per import unit: rename, reorder, remove, add fields; create nested objects from flat columns; move fields via drag-and-drop. JSON output preview updates in real time. Import units can be excluded/included via checkbox. | Transformations are applied to the in-flight mapping; they do not modify the SQL source. | confirmed | S2 | Pro/Base+ only. |
| SQL-migration-1to1 | SQL → MongoDB migration — one-to-one relationship mapping | Supported (Pro/Base+) | Embed related table's fields in the same document as nested object or same level. Auto-detects foreign keys; falls back to manual join specification. | Auto-detection may miss non-standard FK naming conventions. | confirmed | S2 | Pro/Base+ only. |
| SQL-migration-1to-many | SQL → MongoDB migration — one-to-many relationship mapping | Supported (Pro/Base+) | Embed as array of objects. Auto-detects FK. Array element content options: Object with fields per column, values only (array of scalars), or custom. Reuse / clean up unused datasets from prior mapping steps. | One-to-many embed creates potentially large arrays; no automatic size warning. | confirmed | S2 | Pro/Base+ only. |
| SQL-export-field-map | MongoDB → SQL migration — field mapping types | Supported (Pro/Base+) | Four mapping types: Column (primitive field → SQL column), Object Fields (embedded document → flat columns), Array Elements to Rows (array → one row per element + index column), Array Elements to Columns (array → columns with numeric suffixes). Auto-detects SQL type from most frequent MongoDB type in last 50 documents; "Mixed" if conflicting types found. _id used as PK by default (unless string type on MySQL). | Requires Pro/Base+ edition. Auto-detection based on 50 documents may be unreliable on small or sparse samples. | confirmed | S3 | Pro/Base+ only. |
| SQL-export-relations | MongoDB → SQL migration — relationship types | Supported (Pro/Base+) | Four relationship options per sub-document or array: Embed (no new table — flatten into parent), Table PK←FK (new table with FK referencing parent PK), Table FK→PK (parent gets FK referencing new table's PK), Table No Link (new table, no foreign key). | Relationship type choice directly determines the SQL schema output; incorrect selection requires re-migration. | confirmed | S3 | Pro/Base+ only. |
| SQL-export-monitor | MongoDB → SQL migration — preview and monitoring | Supported (Pro/Base+) | SQL Table preview (shows projected SQL schema), SQL Statement preview (CREATE TABLE + INSERT statements), Log Messages preview. Live export monitor with detailed stats + log messages during run. Revert completed export option. Log files viewable from Operations sidebar. | Revert option availability is unverified after partial failures. | confirmed | S3 | Pro/Base+ only. |
| SQL-export-targets | MongoDB → SQL migration — supported targets | Supported (Pro/Base+) | MySQL, Microsoft SQL Server, Oracle, PostgreSQL, IBM DB2, Sybase. (Note: Import SQL source is MySQL, PostgreSQL, Oracle, SQL Server only — IBM DB2 and Sybase are export targets only.) | Requires Pro/Base+ edition. Target SQL database connection required. | confirmed | S3 | Pro/Base+ only. |
| SQL-reschema | Reschema — in-place schema migration | Supported (Pro/Base+) | Move an existing collection to a new schema in-place (no migration scripts needed). Operations: add, delete, rename, reorder, flatten, extract fields and arrays. Schedulable as a task via Task Scheduler. | Requires Pro/Base+ edition. Reschema is an in-place write operation; requires collection write access. Irreversible without backup. | confirmed | S1 | Pro/Base+ only. |
