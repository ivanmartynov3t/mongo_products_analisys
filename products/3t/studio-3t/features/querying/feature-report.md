## Scope

This report covers Studio 3T's querying capabilities: the Collection Tab query bar, result views (Table, Tree, JSON), in-place editing, the Visual Query Builder (VQB), Date Tags, IntelliShell, Query Manager, cross-collection Value Search, GridFS viewing, and two dictionary entries (split-panel views, charts/dashboards) that could not be corroborated in source.

## Behavioral walkthrough

Studio 3T provides a layered querying experience designed to serve users ranging from beginners (VQB drag-and-drop) to power users (IntelliShell scripting). The Collection Tab query bar is the default entry point: it accepts raw MongoDB query JSON with BSON extensions, autocomplete, and five query-shaping fields (Query, Projection, Sort, Skip, Limit). A shorthand system allows typing a bare ObjectId hex or UUID string and having it auto-expanded into a properly typed query — a practical convenience for _id lookups. The query bar's autocomplete is not bespoke to the query bar: `QueryAutoCompletion.java`, `AggregationAutoCompletion.java`, `MongoScriptAutoCompletion.java`, and `MongoContentAssistProcessor.java` form one shared autocompletion framework reused by the Collection Tab query bar, the Aggregation Editor, and IntelliShell (documented as `SHELL-autocomplete`).

Result display offers three views: Table View (spreadsheet-style with column reorder, hide, and expand-embedded-field navigation), Tree View (hierarchical JSON tree with in-place editing), and JSON View (raw document display with a full Document JSON Editor). The Table View is especially mature: it supports stepping into arrays and embedded objects through a breadcrumb navigation trail, BSON type coloring, and direct copy-as-CSV or copy-for-Excel exports. In-place editing is available in all three views, and the multi-document update dialog provides an updateMany-equivalent workflow without writing shell code. **Note:** these result-view sub-features were not independently re-verified in the 2026-07 source-code audit (the investigated directories did not include the result-view/`CollectionViewer` code) — they remain as previously documented, unconfirmed by this pass.

**Edition gating (corrected 2026-07-31):** a source-code audit found that several sub-features previously documented as "All editions" are gated against the Free edition. `AppFeatures.SAVED_QUERIES_AND_HISTORY` — which underlies query history, default-query-per-collection, and the Query Manager's collection/IntelliShell/aggregation query types — is present in the Community (Robo) edition but **absent from Free** (`utils/Edition.java:96-120`). `AppFeatures.VISUAL_QUERY_BUILDER` is checked more strictly still: it is present only from the `PROFESSIONAL` feature set up (inherited by Core/Pro/Enterprise) and is **absent from both Free and Community (Robo)** (`utils/Edition.java:51,96-120`; `dataman/mongodb/gui/querybuilder/QueryBuilder.java:1007,1019,1031`). In practice: Free edition lacks saved queries/history, the Query Manager (non-SQL types), and the entire Visual Query Builder; Community (Robo) edition gets saved queries/history and the Query Manager but still lacks VQB. Code generation (Query Code tab, any language including MongoDB Shell) is likewise Professional-tier-and-up only. These corrections should be treated as high-confidence, based on direct enum-membership evidence in `Edition.java` rather than inference, though the mapping from internal `Edition` enum names (`ROBO`, `FREE`, `CORE`, `PRO`, `PROFESSIONAL`, `ENTERPRISE`) to Studio 3T's current public-facing tier names should be confirmed by a human before external publication.

The Visual Query Builder deserves specific attention. It operates as a drag-and-drop interface where fields and values from Table View or Tree View cells can be dragged directly into query condition rows. The VQB and the Query Bar stay bidirectionally in sync in real time — any change in one immediately updates the other. The VQB also generates query code live in the Query Code tab, making it a learning tool for MongoDB query syntax as well as a productivity tool. Array querying is supported through a dedicated "Has array element(s) matching" mode. As noted above, VQB (core, projection/sort sections alike) requires Professional tier or higher and is unavailable in both Free and Community editions.

**Code-generation languages (corrected 2026-07-31):** the Query Code tab's generator registry (`t3/utils/codegenerators/ProgramCodeGenerators.java:31-41`) implements exactly 9 language generators, previously described loosely as "Node, Java, Python, etc." The precise list: MongoDB Shell, JavaScript (Node.js), Java (2.x driver API), Java (3.x driver API), Java (4.x driver API), C#, Python, PHP, and Ruby. Each non-MongoShell generator is gated by its own `AppFeatures.QUERY_CODE_GENERATION_*` entry, all available from the Professional tier up only.

Date Tags are a cross-cutting feature unique to Studio 3T. Rather than manually writing ISODate range expressions, users write semantic tags like `#lastcalmonth` or `#last7days` that expand to {$gt, $lt} date ranges at runtime. Tags are supported in every query entry point: Collection Tab, IntelliShell, VQB, Aggregation Editor $match stages, and Export query filters. This remains an actively maintained feature (fixes in 2026.11.0 and 2025.4.0).

IntelliShell is a mongosh-based shell embedded in the IDE. It adds two modes: Shell mode (raw script execution) and Query Assist mode (which intercepts standalone find/aggregate calls and opens them as editable result tabs with Query Code and Visual Explain). This bridges the gap between shell scripting and structured result management. Destructive operation warnings and per-session suppressibility add a safety layer.

### Value Search (new — undocumented capability, not yet in feature dictionary)

Studio 3T Desktop implements a cross-collection value/field search capability — "Search in…" — that was not previously documented under any `QUERY-*` ID. It is implemented in `t3/dataman/gui/search/SearchTab.java` (1517 lines) and `t3/utils/ValueSearcher.java`, and lets a user search a chosen set of collections in a database for a literal value and/or field name, with case-sensitive and regex toggles. It supports three distinct search modes: field value and name (`VALUE_NAME`), field value only (`VALUE`), and field name only (`NAME`) (`ValueSearcher.java:246-260`). This is a materially different capability from the query bar/VQB, which filter a single collection — Value Search operates *across* an arbitrary set of collections. It is gated by `AppFeatures.VALUE_SEARCH`, available from the Professional tier up (`utils/Edition.java:59`). Recent history: field-name search mode was added in 2022.8.0 ("Enhanced Value Search"); a diacritics case-sensitivity fix shipped in 2024.5.0. A proposed sub-feature ID, `QUERY-value-search`, has been added to `feature-matrix.md` marked **PENDING DICTIONARY ADDITION** — it needs to be formally added to `feature-dictionary.md` before being treated as a permanent ID.

### Unconfirmed dictionary entries: split-panel views and charts/dashboards

Two sub-feature IDs added to the dictionary on 2026-07-28 — `QUERY-view-split` (split-panel/synchronized-scrolling document comparison) and `QUERY-charts-dashboards` (build charts from collection/query/pipeline data into saved dashboards) — were added from studio3t.com marketing copy rather than a source-code check. This audit's exhaustive search of the full `data-man-mongodb-ent/src/main/java` tree (`grep` for `SplitPanel`, `sync scroll`, `side-by-side`, and `dashboard`) found **zero corroborating code** for either capability. The only tangentially related code is `dataman/gui/statsview/ServerStatusChartsTab.java` (server status metrics, an F-IDX concern) and AI Helper markdown chart rendering (response formatting, not a query-result chart/dashboard builder). Both sub-features are flagged **absent/unverified** for Studio 3T Desktop pending confirmation of whether the underlying capability exists in an unexamined part of the codebase — they should not be presented as confirmed, shipped functionality until that recheck happens.

## Constraints and risks

- Date Tags are Studio 3T–specific syntax and will not execute if a query is copied to a native mongosh session outside the tool.
- VQB sync is bidirectional but operates at the Collection Tab level; complex shell scripts in IntelliShell are not represented in the VQB.
- Shared folder query save requires Pro/Base+ edition — Free users are limited to local file storage.
- IntelliShell Query Assist mode is scoped to standalone find() and aggregation() calls; complex multi-step scripts use Shell mode only.
- **Edition gating is broader than previously documented (corrected 2026-07-31):** query history/default-query and the Query Manager (non-SQL types) are unavailable in Free edition (present in Community/Robo and up); the entire Visual Query Builder and all code generation are unavailable in both Free and Community (Robo) editions, requiring Professional tier or higher. Anywhere this report previously implied "All editions" for these capabilities, that claim was incorrect.
- `QUERY-view-split` and `QUERY-charts-dashboards` should not be presented as shipped Studio 3T Desktop capabilities — no corroborating source code was found for either during this audit.

## Conclusion

Querying is one of Studio 3T's strongest feature areas. The combination of VQB bidirectional sync, Date Tags, IntelliShell's Query Assist mode, mature Table View navigation, and cross-collection Value Search makes Studio 3T competitive for a wide range of MongoDB querying workflows from simple document lookup to complex aggregation pipeline development. The key differentiator versus MongoDB Compass is the IntelliShell Query Assist bridge between scripting and structured result management. Two marketing-sourced dictionary entries — split-panel comparison views and a chart/dashboard builder — could not be corroborated against the source code and should be treated as unverified until a further check is done. Several edition-gating claims in prior versions of this report and its companion matrix overstated Free-edition availability for query history, the Query Manager, and the Visual Query Builder; see the corrections above, based on direct `Edition.java`/`AppFeatures.java` evidence as of 2026-07-31.
