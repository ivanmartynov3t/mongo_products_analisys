| SHELL-engine | Shell engine — mongosh integration | Supported | mongosh/mongo executable bundled with Studio 3T; can be overridden per connection or globally in Preferences > Tools > IntelliShell. Custom path to an external mongosh binary is configurable. Format code (Ctrl+Alt+L). Indent/unindent (Tab/Shift+Tab). Line comments (Ctrl+/). Date tags support. mongosh runs as a real external process (`ProcessBuilder`), with two selectable host implementations: current mongosh and a legacy `mongo`-binary host. | mongosh binary must be accessible at the configured path; custom path must point to a compatible mongosh version. **Overriding the mongosh path also silently force-disables Query Assist mode** (see SHELL-modes) — a currently-undocumented side effect. | confirmed | S1 | All editions. **Editor engine correction (medium confidence, needs follow-up):** the dictionary's "Monaco" claim for the underlying editor engine is not supported by code found in this pass — the editor is a custom Eclipse JFace/SWT `StyledText`-based component (`t3/utils/editors/json/Editor.java`), not Monaco. The exploring agent did not exhaustively rule out a secondary Monaco-based surface elsewhere in the codebase; recommend a repo-wide "monaco" search before finalizing this correction. | SHELL-autocomplete | Auto-complete | Supported | Auto-completion triggered by Ctrl+Space (and automatically in context). | SHELL-validation | Syntax validation | Supported | Live error highlighting as code is typed. Errors indicated by: red gutter crosses (left margin), right-ruler markers (right scrollbar). | SHELL-run-all | Run all — F5 | Supported | F5 executes the entire script top-to-bottom. In Shell mode, output appears in Raw shell output tab. | SHELL-run-cursor | Run to cursor — F6 | Supported | F6 executes the script from the beginning to the cursor's current line. Useful for step-through debugging of large scripts. | — | confirmed | S1 | All editions. |
| SHELL-run-select | Run selected — F9 | Supported | F9 (or Ctrl+Enter on selected text) executes only the currently highlighted/selected text block. | SHELL-modes | Execution modes — Shell vs Query Assist | Supported | Two modes switchable per IntelliShell tab. Shell mode: all output goes to the Raw shell output tab only; no editable result tabs are opened; useful for administrative scripts with non-query output. Query Assist mode (default for find/aggregation): each standalone find() or aggregation pipeline call opens a dedicated, editable result tab labelled with the source line number; supports inline editing, Visual Explain, Query Code tab, and pinned tabs. Destructive operation warnings (update/delete/drop) displayed in Query Assist mode; suppressible per session. | Query Assist mode result tabs apply only to standalone find() and aggregation pipeline calls; other shell output still appears in the Raw tab. | confirmed | S1 | All editions. |
| SHELL-result-tabs | Result tabs (Query Assist mode) | Supported | In Query Assist mode each query in the script that produces a cursor (find, aggregation) opens a separate result tab. Tab label includes the source line number for traceability. Tabs support: inline document editing (Tree/Table/JSON view), pin tab (keep open across re-runs), close individual tabs, re-run from tab. | Only available in Query Assist mode. Result tabs for the same script are replaced on each re-run unless pinned. **The number of concurrently open result tabs is capped by default** (user-togglable preference `shouldLimitNumberOfIntelliShellResultTabs`, default on) — see new `SHELL-result-tab-limit` row below. | confirmed | S1 | All editions. |
| SHELL-result-views | Result view modes | Supported | Each result tab supports the full Studio 3T result view suite: Tree View (hierarchical), Table View (rows/columns with inline edit), JSON/BSON View (raw document), Query Code tab (generated MongoDB Shell, Node.js, Java, C#, Python, PHP, Ruby code), Visual Explain tab (explain plan visualization). | Visual Explain is only available in Query Assist mode; not available in Shell mode. | confirmed | S1 | All editions. |
| SHELL-save-load | Save & load scripts | Partial / unverified | Confirmed: save current script as a .js file (`Save script`/`Save script as…`) and load/open a .js file from disk, bound to the generic file save/open actions. Filename date/time placeholders usable in script output paths for unique filenames per run (e.g., #today). **Unverified: "Save to Query Manager (as IntelliShell Script query type)"** — no code evidence was found wiring IntelliShell scripts into the Query Manager; the actions used (`MAIN_MENU_FILE_SAVE_FILE`/`MAIN_MENU_FILE_OPEN_FILE`) are distinct from the separate Query Bar save/load actions (`MAIN_MENU_QUERY_SAVE_QUERY`/`MAIN_MENU_QUERY_LOAD_QUERY`), which were not confirmed as wired into IntelliShell either. | .js file saves do not retain Studio 3T connection context. Query Manager save/load claim needs re-verification — may exist via a code path not covered by this pass, so treat as unverified rather than confirmed-wrong. | confirmed (file save/load); **unverified (Query Manager linkage)** | S1, S2 | All editions. See [findings](../../../../../research/studio-3t-desktop-review-2026/07-shell-findings.md#sub-feature-status-re-check) (medium confidence on the Query Manager correction). |
