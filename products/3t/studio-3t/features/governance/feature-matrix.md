## Scope note

This file previously documented the Studio 3T platform's governance-tier products (3T Lens, 3T Access, 3TL Bridge) and 3T Explore's governance-relevant aspects as sub-sections of Studio 3T. As of 2026-07-29, each of those products has been split into its own product folder under `products/3t/` with its own `product-report.md` and `features/governance/{feature-matrix.md,feature-report.md}`. See the pointer table below for those platform-tier IDs.

The Desktop IDE's own native governance capabilities are now authored below, based on a 2026-07-31 source-code audit of `product-suite/data-man-mongodb-ent/src/main/java/t3/` in the `3t.tools` repo (branch `KONG-11077-No-scroll-bar-on-linux-2`, commit `435d6844a3a`). See the [research findings](../../../../../research/studio-3t-desktop-review-2026/10-governance-findings.md) for full evidence. Several of these corrections **narrow or replace** claims previously carried by reference only (never before given a dedicated row in this file) — most notably `GOV-audit-log`, `GOV-cred-storage-os`, and `GOV-startup-policy`.

### Related narrative (not a dedicated sub-feature ID)

Ultimate-edition gating of Kerberos/LDAP/AWS IAM/OIDC (tracked under `CONN-auth-enterprise` in F-CONN, not a F-GOV ID) is confirmed accurate and enforced, not just labeling: `Edition.ENTERPRISE` ("Ultimate") is the only edition with `AppFeatures.KERBEROS_AND_LDAP_AUTH`, `AWS_IAM`, `OIDC`. `AuthenticationPages.java` allows creating/editing/testing a connection with a restricted auth method on a lower tier, but blocks actual connect with a non-dismissable upgrade warning (`AuthenticationPages.java:948-983`). Kept as-is per the audit.

## Feature-level conclusion

### Confirmed strengths

- Real, enforced read-only lock (`GOV-readonly-mode`) and network-policy outbound kill switch (`GOV-network-policy`).
- Mature MongoDB server-side RBAC (users, roles, inheritance, privilege tree — `GOV-rbac-*`), available from Professional tier upward.
- Functional, mature rule-based data-masking engine (`GOV-data-masking`), correctly scoped away from PII classification/compliance templates (those remain 3T Lens/3TL Bridge concepts).
- Telemetry controls and Ultimate-edition enterprise-auth gating are real and enforced, not just labeled.

### Confirmed limitations

- `GOV-audit-log` is far narrower than documented: only Connection Manager actions are logged locally (off by default, Windows-GPO-only), and no query or document-modification audit trail exists in the Desktop IDE. The newer HTTP audit sender to 3T Access (`AuditEventSender`) is unwired scaffolding with zero call sites, not a shipped capability.
- `GOV-cred-storage-os` and `GOV-startup-policy` were previously documented as OS-credential-API and EJSON/YAML-config mechanisms respectively; neither exists — the real mechanisms are a local BouncyCastle keystore file and Windows registry/Group Policy/manifest, respectively.
- `GOV-cli-policy` is absent (only one unrelated CLI flag exists); likely a documentation carry-over from MongoDB Compass.
- `GOV-protect-mode` has no distinct supporting code — likely a duplicate/alias of `GOV-readonly-mode`, flagged rather than removed.
- `GOV-isolated-edition` is absent for Studio 3T within the audited source tree (only found as a MongoDB Compass detection string).

### Open questions / unknowns

- `GOV-air-gapped`: plausible from the licensing architecture but not directly confirmed — needs a dedicated licensing-flow trace.
- `GOV-ai-controls`: admin switch and licensed tier confirmed; full approval/disclosure UX flow needs a dedicated F-AI cross-check.
- `GOV-rbac-actions`: structurally confirmed, but completeness against MongoDB's full documented action catalogue not exhaustively diffed.
- `GOV-isolated-edition`: only `product-suite/` was searched; a packaging-level variant outside this tree cannot be fully ruled out.
- Whether `GOV-audit-log` should be split into a shipped local-log ID and a separate roadmap ID for the unwired `AuditEventSender` HTTP sender — flagged for central synthesis (dictionary changes are out of scope for this file).
